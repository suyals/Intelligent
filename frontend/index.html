📐 Comprehensive System Architecture & Design

1. Data Pipeline & Schema Discovery

The system was built upon the actual datasets provided in the data/ directory:

  • data/student_query_train_5000.csv: 5,000 labeled records with schema (ID, Student_Query, Priority).
  • data/student_query_test_1000.csv: 1,000 labeled records with identical schema.
  • Zero missing values: Complete data integrity across all columns.
  • Ground-Truth Target: Priority (3 balanced classes: High, Medium, Low).
  • Domain Categorization: 7 functional institutional departments (Academics & Examination, Finance & Accounts, Registrar & Student Records, IT & Technical Support, Hostel & Housing, Campus Facilities & Transport, Student Affairs & Clubs).

2. NLP Preprocessing & Feature Engineering

Incoming student queries undergo rigorous natural language normalization:

  • Text Normalization: Lowercase transformation and contraction expansion (e.g. "can't" → "cannot").
  • Regex Tokenization: Stripping extraneous symbols and punctuation while preserving alphanumeric tokens.
  • TF-IDF Vectorization: Sublinear TF scaling with ngram_range=(1, 2) (unigrams + bigrams), filtering English stop words, producing 162 robust lexical features.

3. Model Selection & Cross-Validation Methodology

Four candidate classification algorithms were benchmarked using 5-Fold Stratified Cross-Validation on the training dataset to ensure zero data leakage:

  • Logistic Regression (Selected): Maximum entropy model providing calibrated class probabilities and interpretability.
  • Calibrated Linear SVM: Linear Support Vector Machine with 3-fold Platt calibration.
  • Multinomial Naive Bayes: Probabilistic bag-of-words classifier with Laplace smoothing.
  • Random Forest Classifier: Ensemble of decision trees.

4. Explainability & Triage Automation

The system generates transparent reasoning for every prediction by calculating the most influential TF-IDF feature weights for each query and matching them against institutional priority rules and departmental SLAs.
